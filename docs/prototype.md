# nonsul-coach 프로토타입 명세

## 1. 프로토타입 목적

`nonsul-coach`의 첫 프로토타입은 학생이 작성한 논술 답안을 목표 대학교의 실제 평가 기준에 맞춰 분석하고, 학생이 답안을 스스로 고칠 수 있는 구체적인 피드백을 제공하는 경험을 검증한다.

화면의 완성도나 기능의 수보다 다음 질문에 답하는 것을 우선한다.

- 피드백이 목표 대학교와 해당 기출문제의 요구사항을 정확히 반영하는가?
- 피드백의 판단 근거를 학생 답안에서 직접 확인할 수 있는가?
- 학생이 피드백을 읽고 무엇을, 왜, 어떻게 고쳐야 하는지 이해할 수 있는가?
- AI가 완성 답안을 대신 작성하지 않고 학생의 자기 수정을 유도하는가?

## 2. 프로토타입 범위

### 포함

- 목표 대학교 1곳
- 공식 자료가 확보된 실제 기출문제 2~3개
- 목표 대학교 및 기출문제 선택
- 학생의 논술 문제·제시문 직접 입력
- 학생 답안 직접 입력
- 답안 작성 요구사항과 필수요소 검사
- 대학 채점 기준별 피드백
- 답안의 구체적인 문장 또는 문단을 근거로 한 피드백
- 우선 수정 항목 최대 3개
- 학생의 자기 수정을 돕는 질문과 수정 행동 안내
- 수정한 답안 다시 분석하기

### 제외

- 회원가입 및 학생 계정
- 학생별 학습 이력 저장
- 교사용 대시보드
- 학급 단위 통계
- 합격 가능성 예측
- 공식 근거가 없는 총점 또는 등급 산출
- AI가 작성한 완성 답안 제공
- 여러 대학을 동시에 비교하는 기능

## 3. 사용자와 시스템 역할

### 시스템

- 선택한 목표 대학교의 채점 기준을 적용한다.
- 해당 기출문제의 공식 해설, 답안 요구사항, 필수요소를 기준으로 분석한다.
- 대학이 제공한 공식 예시답안을 논리 구성과 필수 내용 확인에 활용한다.
- 학생 답안의 실제 문장 또는 문단을 피드백 근거로 제시한다.
- 학생이 답을 베껴 쓰지 않고 스스로 수정할 수 있도록 질문과 수정 방향을 제공한다.

### 학생

- 목표 대학교와 기출문제를 선택한다.
- 문제와 제시문을 직접 입력한다.
- 자신이 작성한 답안을 직접 입력한다.
- 피드백을 확인하고 답안을 수정한다.
- 수정한 답안을 다시 분석해 개선 여부를 확인한다.

## 4. 대학·기출문제별 평가 패키지

피드백의 품질을 확보하기 위해 기출문제마다 다음 자료를 하나의 평가 패키지로 관리한다.

| 항목 | 내용 |
| --- | --- |
| 대학 정보 | 대학교명, 전형, 계열 |
| 문항 정보 | 연도, 문항 번호, 문제 유형 |
| 문제 자료 | 논술 문제와 제시문 |
| 작성 요구사항 | 분량, 형식, 수행 과제, 사용해야 할 제시문 |
| 필수요소 | 답안에 반드시 포함되어야 하는 개념과 논리 요소 |
| 감점 조건 | 누락, 논제 이탈, 형식 위반 등 공개된 감점 기준 |
| 채점 기준 | 대학이 공개한 평가 항목과 항목별 설명 |
| 공식 해설 | 출제 의도와 문항 해설 |
| 공식 예시답안 | 필수 내용과 논리 구성 비교를 위한 참고 자료 |
| 출처 정보 | 자료 출처, 발표 연도, 버전 |

공식 예시답안은 학생에게 모범 문장을 생성해 주기 위한 자료로 사용하지 않는다. 다음 항목을 판별하기 위한 내부 기준으로만 사용한다.

- 반드시 다뤄야 할 개념
- 제시문 간 비교·대조 기준
- 요구된 논증 단계
- 제시문을 근거로 활용하는 방식
- 결론에서 충족해야 할 내용

## 5. 화면 구성

프로토타입은 한 화면 안에서 `입력`과 `피드백` 두 상태를 제공한다.

### 5.1 입력 영역

다음 항목만 표시한다.

1. 목표 대학교 선택
2. 기출 연도·문항 선택
3. 논술 문제·제시문 입력란
4. 학생 답안 입력란
5. `피드백 받기` 버튼

개인정보 입력을 방지하기 위해 입력란 주변에 다음 내용을 안내한다.

> 이름, 학교명, 연락처 등 개인정보는 입력하지 마세요. 입력한 답안은 피드백 생성에만 사용됩니다.

### 5.2 피드백 영역

입력 내용은 유지하고 같은 화면 아래에 다음 순서로 결과를 표시한다.

1. 필수 요구사항 검사 결과
2. 대학 채점 기준별 진단
3. 가장 먼저 수정할 항목 최대 3개
4. 학생 답안에서 찾은 판단 근거
5. 스스로 고칠 수 있도록 돕는 질문과 수정 행동
6. 수정 답안 입력 및 `다시 피드백 받기`

## 6. 피드백 판단 우선순위

피드백은 다음 우선순위를 반드시 따른다.

1. 문항에 명시된 답안 작성 요구사항
2. 목표 대학교가 공개한 채점 기준
3. 공식 해설과 필수 답안 요소
4. 공식 예시답안의 논리 구성
5. 일반적인 논술문 품질

상위 기준과 하위 기준이 충돌하면 상위 기준을 따른다. 문장이 자연스럽더라도 문제에서 요구한 비교 대상이나 필수 개념이 빠졌다면 표현보다 요구사항 미충족을 먼저 피드백한다.

## 7. 피드백 결과 구성

### 7.1 필수 요구사항 검사

다음과 같이 객관적으로 확인할 수 있는 항목은 규칙 기반 검사를 우선한다.

- 글자 수 범위
- 사용해야 할 제시문
- 필수 단어 또는 개념
- 문단 수와 답안 형식
- 요약, 비교·대조, 비판, 적용 등 문항이 요구한 수행 과제

각 항목은 `충족`, `부분 충족`, `미충족`, `확인 필요` 중 하나로 표시한다.

### 7.2 대학 채점 기준별 진단

평가 패키지에 정의된 채점 항목별로 다음 내용을 제공한다.

- 평가 항목
- 충족 수준
- 학생 답안의 근거 문장 또는 문단
- 해당 판단의 이유
- 보완해야 할 내용

초기 프로토타입에서는 임의의 총점이나 합격 가능성을 제공하지 않는다. 대학이 배점과 계산 방식을 명확하게 공개한 경우에만 공식 기준에 따른 점수를 표시한다.

### 7.3 우선 수정 항목

학생이 한 번에 실행할 수 있도록 가장 중요한 피드백을 최대 3개로 제한한다.

우선순위는 다음과 같다.

1. 문제의 명시적 요구사항 또는 필수요소 누락
2. 핵심 주장과 근거 사이의 논리 문제
3. 제시문 활용과 비교·대조의 문제
4. 문단 간 연결과 전체 일관성 문제
5. 문장 표현 문제

## 8. 개별 피드백 형식

모든 개별 피드백은 다음 여섯 요소로 구성한다.

| 요소 | 설명 |
| --- | --- |
| 평가 항목 | 어떤 대학 채점 기준에 대한 판단인지 표시한다. |
| 답안 근거 | 학생 답안의 실제 문장 또는 문단을 인용한다. |
| 판단 | `충족`, `부분 충족`, `미충족`, `확인 필요`로 표시한다. |
| 판단 이유 | 대학 기준과 비교해 무엇이 충족되거나 부족한지 설명한다. |
| 수정 질문 | 학생이 부족한 사고 과정을 스스로 채울 수 있도록 질문한다. |
| 수정 행동 | 어느 위치에서 무엇을 보완할지 구체적으로 안내한다. |

### 피드백 예시

> **평가 항목:** 제시문 비교·대조
>
> **답안 근거:** “제시문 (가)는 개인의 자유를 강조하고, 제시문 (나)는 공동체를 강조한다.”
>
> **판단:** 부분 충족
>
> **판단 이유:** 두 제시문의 입장은 언급했지만, 대학 채점 기준이 요구하는 ‘동일한 쟁점에 대한 판단 기준의 차이’가 설명되지 않았다.
>
> **수정 질문:** 두 제시문은 개인의 선택을 평가할 때 각각 무엇을 가장 중요한 기준으로 보는가?
>
> **수정 행동:** 인용한 문장 다음에 두 입장의 판단 기준을 직접 대비하는 문장 한 개를 추가한다.

## 9. 피드백 작성 원칙

- 학생의 답안을 대신 작성하지 않는다.
- 수정된 완성 문장을 바로 제시하지 않는다.
- 학생이 제시하지 않은 새로운 주장을 추가하지 않는다.
- 모든 지적은 학생 답안이나 공식 문제 자료의 구체적인 근거와 연결한다.
- “부족하다”, “어색하다”와 같은 평가만 단독으로 제시하지 않는다.
- 불확실한 판단은 단정하지 않고 `확인 필요`로 표시한다.
- 공식 자료에 없는 역사적 사실, 통계, 인용을 생성하지 않는다.
- 표현 개선보다 문항 요구사항과 논리 구조를 우선한다.
- 한 번의 분석에서 핵심 수정 과제를 최대 3개만 우선 제시한다.
- 학생이 답을 찾을 수 있도록 질문과 수정 목표를 함께 제공한다.

## 10. 분석 처리 흐름

```text
목표 대학교·기출문제 선택
            ↓
대학·문항별 평가 패키지 불러오기
            ↓
학생이 논술 문제·제시문·답안 직접 입력
            ↓
분량·형식·필수요소 규칙 검사
            ↓
대학 채점 기준에 따른 답안 분석
            ↓
답안 근거와 공식 자료에 대한 재검증
            ↓
우선순위 피드백 최대 3개 제공
            ↓
학생 수정 후 다시 분석
```

AI 분석은 다음 두 단계로 나눈다.

1. 채점 기준별로 답안을 분석하고 구조화된 피드백 후보를 생성한다.
2. 각 지적이 학생 답안과 공식 자료에 근거하는지 검사하고, 근거 없는 지적은 제거하거나 `확인 필요`로 변경한다.

## 11. 프로토타입 성공 기준

다음 조건을 충족하면 프로토타입의 핵심 목적을 달성한 것으로 본다.

- 모든 피드백이 특정 대학 채점 기준 또는 문제 요구사항과 연결된다.
- 모든 문제 지적에 학생 답안의 근거 위치가 표시된다.
- 필수요소 누락이 일반적인 표현 문제보다 먼저 표시된다.
- 우선 피드백이 최대 3개로 정리된다.
- 각 우선 피드백에 판단 이유, 수정 질문, 수정 행동이 포함된다.
- 공식 예시답안의 문장을 학생에게 그대로 제공하지 않는다.
- 학생이 수정한 답안을 같은 기준으로 다시 분석할 수 있다.
- 교사가 검토했을 때 판단 근거와 수정 방향을 이해할 수 있다.

## 12. 배포 방식

프로토타입은 한 화면짜리 웹 앱으로 구현해 ChatGPT Sites의 제한 공유 링크로 배포한다.
