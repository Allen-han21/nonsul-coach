# nonsul-coach

학생의 논술문을 자연어 처리 기반으로 분석해 **논리 구조·근거·일관성**을 교육용 수준에서 점검하고, 학생이 스스로 글을 고칠 수 있도록 구체적인 개선 방향을 제시하는 논술 첨삭 시스템입니다.

> 현재는 프로젝트 기획 및 초기 설계 단계입니다. 특정 AI 모델이나 분석 정확도가 이미 구현·검증되었다고 전제하지 않으며, 일반적인 텍스트 분석 원리를 교육 목적에 맞게 단순화한 분석 틀부터 구축합니다.

## 문제 정의

논술 첨삭은 단순히 문장을 매끄럽게 고치는 작업이 아닙니다. 학생이 자신의 주장을 분명히 제시했는지, 근거가 주장을 충분히 뒷받침하는지, 문단과 문단이 일관된 흐름으로 연결되는지를 구체적으로 이해할 수 있어야 합니다.

`nonsul-coach`는 답안을 대신 작성하거나 정답을 단정하는 도구가 아니라, 다음과 같은 논리적 허점을 학생이 직접 발견하고 수정하도록 돕는 **교육용 글쓰기 코치**를 지향합니다.

- 근거가 부족하거나 주장만 제시된 부분
- 예시와 주장의 연결이 약한 부분
- 문단 사이의 전환이 부자연스러운 부분
- 앞뒤 주장 또는 개념 사용이 일관되지 않은 부분
- 논제나 제시문의 요구에서 벗어난 부분
- 분량, 필수 단어 등 답안 작성 조건을 충족하지 못한 부분

## 핵심 분석 영역

### 1. 논리 구조 분석

- 글의 핵심 주장과 문단별 중심 문장을 식별합니다.
- 주장–근거–예시–결론의 연결 구조를 점검합니다.
- 논리적 비약, 순환 논증, 상충하는 주장 등 개선이 필요한 지점을 찾습니다.
- 문제에서 요구한 논제와 답안의 핵심 주장이 일치하는지 확인합니다.

### 2. 근거 제시의 타당성

- 각 근거가 어떤 주장을 뒷받침하는지 확인합니다.
- 근거가 부족하거나 관련성이 낮은 부분을 표시합니다.
- 예시가 단순 나열에 그치지 않고 주장과 명시적으로 연결되는지 점검합니다.
- 검증되지 않은 역사적 사실, 통계, 인용 등을 사실처럼 만들어내지 않습니다.

### 3. 문단 구성의 일관성

- 한 문단이 하나의 중심 생각을 유지하는지 점검합니다.
- 문단 내부의 문장 배열과 접속 관계를 분석합니다.
- 문단 사이의 전환과 전체 글의 흐름이 자연스러운지 확인합니다.
- 핵심 용어와 관점이 글 전체에서 일관되게 사용되는지 살펴봅니다.

## 사용자별 기능 방향

### 학생

1. 기출 연도·문항을 선택해 대학 공식 문제·제시문·작성 조건을 확인하고 자신의 답안을 입력합니다.
2. 시스템이 핵심 주장, 근거 구성, 예시 사용, 문단 관계를 분석합니다.
3. 논리적 허점의 위치와 이유를 문장 또는 문단 단위로 확인합니다.
4. 완성 답안을 대신 받는 것이 아니라, 스스로 수정할 수 있는 질문과 개선 방향을 받습니다.
5. 수정 전후 답안을 비교하며 반복되는 오류를 학습합니다.

피드백 예시:

> 이 문단은 주장을 제시했지만 이를 뒷받침하는 근거가 충분하지 않습니다. 제시문의 원인과 결과 관계를 보여 주는 대목을 근거로 연결해 보세요.

> 예시는 주제와 관련되어 있지만 바로 앞 주장과의 관계가 드러나지 않습니다. 예시가 해당 주장을 어떻게 증명하는지 한 문장으로 설명해 보세요.

### 교사·교육자

- 학생별로 반복되는 글쓰기 오류 유형과 개선 추이를 확인합니다.
- 학급 단위로 자주 나타나는 논리 구조상의 어려움을 파악합니다.
- 수업에서 추가로 설명하거나 연습해야 할 지점을 찾습니다.
- 개별 채점과 반복적인 첨삭에 드는 부담을 줄입니다.

### 보호자

- 학생이 자주 겪는 글쓰기 어려움과 개선 방향을 이해합니다.
- 결과 점수보다 수정 과정과 학습 변화를 중심으로 확인합니다.

## 분석 및 피드백 흐름

```text
기출 선택과 공식 문제·제시문·작성 조건 확인
              ↓
        학생 답안 입력
              ↓
 조건 검사 ─ 논제 일치 검사 ─ 글 구조 분석
              ↓
 주장·근거·예시·문단 연결 관계 점검
              ↓
 오류 위치 + 판단 이유 + 수정 질문 제시
              ↓
     학생의 자기 수정 및 재검토
```

## AI 응답 원칙

### 사실을 만들어내지 않습니다

- 답안이나 제시문에 없는 역사적 사실, 통계, 인물, 출처를 임의로 생성하지 않습니다.
- 확인할 수 없는 내용은 사실로 단정하지 않고 확인 필요성을 명시합니다.
- 제시문 기반 문제에서는 외부 지식을 덧붙이기보다 제공된 자료 안에서 판단합니다.

### 수시 논술의 특수성을 반영합니다

- 제시문의 핵심 요약, 비교·대조, 비판, 적용 등 문제에서 요구한 과업을 우선 확인합니다.
- 글자 수 제한, 필수 단어, 문단 수, 특정 관점 사용 등 명시된 작성 조건을 점검합니다.
- 일반적인 글쓰기 품질과 출제 조건 충족 여부를 구분해 피드백합니다.

### 논제를 이탈하지 않습니다

- 표현을 화려하게 바꾸는 과정에서 출제자가 요구한 답변의 본질을 훼손하지 않습니다.
- 첨삭 제안은 학생의 원래 주장과 문제의 요구 범위 안에서 제공합니다.
- 새로운 주장이나 완성 답안을 대신 작성하기보다, 학생이 수정할 수 있는 방향과 질문을 제시합니다.

### 판단 근거를 설명합니다

- “부족하다”, “어색하다”와 같은 평가만 제시하지 않습니다.
- 문제가 되는 위치, 판단 이유, 개선 목표를 함께 안내합니다.
- 점수 또는 등급을 제공할 경우 평가 기준과 불확실성을 명시합니다.

## 개인정보 보호 원칙

- 학생 이름, 학교, 연락처 등 분석에 불필요한 개인정보는 입력받지 않는 것을 기본으로 합니다.
- 학생 답안은 기본적으로 분석 후 저장하지 않는 방향으로 설계합니다.
- 학습 이력 저장이 필요한 경우 개인정보를 먼저 비식별화하고, 보관 목적과 기간을 명확히 안내합니다.
- 교사용 통계는 개인을 불필요하게 식별할 수 없도록 집계 단위로 제공합니다.
- 실제 서비스 도입 전 관련 법령과 학교의 개인정보 처리 기준을 검토합니다.

## 기대 효과

- 학생이 놓친 논리적 문제를 즉시 확인하고 스스로 개선 방향을 찾을 수 있습니다.
- 동일한 오류의 반복을 줄이고 자기주도적 글쓰기 학습을 강화할 수 있습니다.
- 교사는 학생별·학급별 오류 유형을 효율적으로 파악해 수업을 체계적으로 설계할 수 있습니다.
- 반복적인 개별 첨삭 부담을 줄이고 교사는 고차원적인 지도에 집중할 수 있습니다.
- 글쓰기에 익숙하지 않은 학생도 구조화된 피드백을 통해 초기 진입 장벽을 낮출 수 있습니다.
- 보호자는 학생의 결과뿐 아니라 글쓰기 과정과 개선 추이를 이해할 수 있습니다.

## 개발 원칙

- **교육 우선:** 답안 대필보다 사고 과정과 수정 능력 향상을 우선합니다.
- **근거 기반:** 모든 지적은 답안 또는 제시문의 구체적인 위치와 연결합니다.
- **투명성:** 분석 결과의 근거와 한계를 사용자가 이해할 수 있게 설명합니다.
- **교사 중심 설계:** AI의 평가는 교사의 전문적 판단을 보조하며 대체하지 않습니다.
- **프라이버시 기본값:** 최소 수집, 비식별화, 비저장을 기본 설계 원칙으로 삼습니다.
- **모델 독립성:** 특정 언어 모델에 종속되지 않는 평가 기준과 데이터 구조를 우선 설계합니다.
